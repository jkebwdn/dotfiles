# First-party Clipboard Manager

Baseline `1598e12`; architecture selected 2026-10-03 before implementation.

## Boundary

Quickshell 0.3.1 only exposes focus-dependent `clipboardText`, not a background
MIME offer API. MAGI uses a small original C helper with installed
`ext-data-control-v1` bindings generated by wayland-scanner. It captures the exact
offer, skips the first selection on every connection, ignores primary selection,
and rejects sensitive-marked/unsupported offers before requesting bytes. Python
owns the bounded model, search, storage and restore; QML owns presentation only.
One long-lived Process exchanges JSON lines with the backend; binary capture
uses a length-delimited private pipe. No shell interpolation or cliphist database.
Restore uses installed wl-copy with bytes on stdin and an explicit MIME type.
Build dependencies: cc, wayland-scanner, wayland-client headers, wayland-protocols.
Runtime: Python3, PyGObject/GdkPixbuf, wl-copy. Build artifacts are cached by source
hash outside the repository. Missing dependencies produce an unavailable state.

## Model and privacy

Stable UUID, MIME/category, last-copy timestamp, bounded plain-text preview,
SHA256 identity, pin flag and private payload reference. One preferred format per
offer: URI list, PNG/JPEG, UTF-8/plain text, otherwise HTML converted to plain text.
HTML is never rendered/executed and is restored as plain text. URI lists are
restored as data, never opened or used to read referenced files. No source app
identity is fabricated. Recopy promotes an existing identical item; pins survive
promotion and ordinary clearing. Pinned items stay first in the view.

Default100 entries (10–200 configurable), 50 pins maximum within that limit,
8MiB/item, 256KiB/text, 64MiB total payload; images at most16 million pixels.
Oldest non-pinned entries evict first. A full pinned budget rejects new content.
Search is case-insensitive over stored plain text/URI text, not only excerpts.

Persistence is OFF by default, including pins. Session payloads are in memory;
only bounded image thumbnails use a private0700 runtime directory. On exit these
are removed; stale MAGI thumbnails are cleaned under an exclusive backend lock
on next start. Opt-in disk persistence uses a versioned SQLite database under
XDG_DATA_HOME/magi/clipboard, directory0700/file0600. It is not encrypted; backups
and storage media may retain data. Turning persistence off removes the managed
database. Disabling history pauses capture; deleting and clearing work while
paused. A separate confirmed erase-all action also deletes pinned entries.
Clearing MAGI history does not clear the current clipboard or another manager's
database. Existing copies recorded by the old cliphist watcher are left untouched.

The initial clipboard is never ingested. Capture rejects x-kde-passwordManagerHint
and application/x-keepassxc offers without reading their bytes. Other applications
may omit hints: Wayland has no trustworthy general app identity/private-mode flag,
so automatic password/source exclusion cannot be guaranteed. Pause before copying
sensitive unmarked content. No payload, preview, URI or hash is logged or exposed
by diagnostic IPC. Tests only use synthetic samples; existing cliphist data is not
read/imported/deleted. Its watcher startup is removed and the existing live watcher
was stopped; the 2026-10-04 host audit confirms no cliphist recorder remains.

## Surface and controls

Separate compact centred FloatingWindow, explicit initial dimensions, no reservation
or output-sized input region. A class+title Hyprland rule matches only MAGI Clipboard,
as with Settings. Search gets focus on open; clicking another app releases keyboard
focus while Clipboard can stay open. The initial Exclusive layer-shell design was
replaced after operator feedback that it blocked typing elsewhere. It hides/closes
in true fullscreen using MAGI's existing monitor. One service independent of the
window; current output follows the bar. Multi-output/fractional scale unverified.
Selected palette, existing surface/action radii, semantic Icon with Legacy fallback,
search header, scrollable excerpt cards and rounded bounded image thumbnails.

SUPER+SHIFT+V toggles (SUPER+V retains floating). Search focused on open; Up/Down
select; Enter restores then closes only on success; Escape closes; Ctrl+P pin;
Ctrl+Delete deletes selected (plain Delete edits search); Ctrl+L focuses search.
Mouse restore, pin, delete and clear-unpinned actions remain discoverable.

Settings schema6 adds enabled, historyLimit, persistHistory, includeImages,
includeFiles. Clear-unpinned and confirmed erase-all are actions, not preferences.
Production startup owns activation, so importing the singleton in tests cannot
capture the clipboard. Backend initial offer is skipped on startup/re-enable.

## Acceptance

Model/privacy/cleanup/schema tests precede live capture. Then harmless text,
duplicate, HTML, URI, small image and sensitive samples exercise the real backend.
Check keyboard/mouse/operator appearance, normal notification ownership, one main
1920×1080 layer and48px reservation. No commits or pushes in this milestone.

Core interaction and the corrected FloatingWindow focus behavior are operator-passed.
The final2026-10-04 runtime/test evidence and exact32-path allowlist are recorded in
the [checkpoint](../research/clipboard-manager-checkpoint.md). Whole-shell visual
composition, multi-output and fractional scale remain separate review work.
