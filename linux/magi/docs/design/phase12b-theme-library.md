## Architecture audit before implementation

`theme/palettes/registry.json` is the canonical source for both `ThemeRegistry.qml`
and Python `theme_orchestrator/palette.py`. Ten existing themes comprise four
Catppuccin variants and six Everforest variants. All IDs remain unchanged.
There are 33 required roles and seven selectable accents (red, peach, yellow,
green, teal, blue, lavender), plus the generic accent. Theme.qml already provides
paired on-colours, luminance/contrast/legibleInk helpers and descriptive dark
metadata for shading. Components consume roles rather than theme IDs.
The Settings selector reads registry labels directly; its flat list needs no
new UI. Settings schema 16 stores a string ID; adding options needs no migration.
The current selection and all independent Hub/navigation role names are retained.

The Python resolver expands roles into ANSI, terminal, syntax, diagnostics and
graph colours. Existing adapters own their current outputs only. Hyprland owns
active/inactive borders, Zen remains hybrid, and btop mapping stays unchanged.
The only extra palette constants were four Catppuccin ANSI magentas in Python;
these move into optional registry metadata without changing resolved output.
The asynchronous QML orchestrator serializes requests and drains the latest
selection after completion; no activation redesign is needed.

The light-theme audit found existing semantic foregrounds, backgrounds, hover,
selection, icon tint and shade tokens. The sole literal white component colour
is RoundedArtwork's alpha mask, not visible foreground. Legacy palette QML files
are not the runtime registry. No theme-specific component branches are needed.
Settings/Hub/CC, Calendar, notifications and other surfaces retain their existing
presentation and system-action boundaries.

## Light palettes and readability

No production component redesign was required: existing Latte/Everforest light
support already supplies semantic ink, layers and dark/light shade direction.
The native lock's existing palette reader and LockTokens also accept new IDs;
only offline token bindings are exercised. No lock binary is built or installed.

[Contrast report](previews/phase12b/contrast.json) measures main text on background,
surface and elevated, every paired button ink, all accent labels on surface, and
muted text. Main text clears 3:1 everywhere; paired ink clears 4.5:1. Values below
4.5:1 are explicitly flagged rather than changing upstream colours. Tokyo Night
Day's blue foreground on its denser surfaces is below 4.5:1; several Dawn accents,
Nord accents and upstream comment colours also fall below that threshold. This
is not a WCAG conformance claim. Native review should focus on small text,
selected navigation, disabled controls and muted labels, especially Day/Dawn.

## Orchestrator and safety

One registry feeds shell, Settings, native lock palette reading and Python
snapshot resolution. Optional `ansiMagenta` metadata replaces four existing
Catppuccin constants in Python; fallback remains lavender. No application adapter
is redesigned. Isolated renders cover MAGI, Hyprland borders, Ghostty, GTK/Thunar,
Zen aliases, Yazi/yatline, Neovim, Starship, Fastfetch ANSI and btop baseline.
Fastfetch consumes the terminal ANSI integration rather than a new theme file.
GTK's existing light/dark Adwaita base selection remains intact. Application hooks
and commands in lifecycle tests are mocked and point into disposable roots.

Tests parse generated TOML, syntax-check Lua, check CSS structure, verify Ghostty's
16 ANSI entries, validate every canonical colour, and compare repeated renderer
bytes and idempotent published outputs. These checks do not substitute for later
native application review. Rapid QML switching exercises the real asynchronous
bridge with only a disposable Ghostty integration and confirms last-request-wins.
Generated output is retained under `/tmp/magi12b/output`, never live theme paths.
