## Evidence and scope

**Verified source** means inspected declarations/control flow, not observed
runtime behavior. **Intent** means upstream comments or documentation.
**Proposal/risk** means our interpretation requiring testing. Neither K4 nor
an experimental MAGI shell was launched. No performance, keyboard, connection
or compositor tests were performed.

## K01 — Compact and expanded content share a host surface

**Verified source:** [shell.qml:278–307][host] creates one PanelWindow per
screen. At lines 573–677 it anchors to the configured bar edge, requests
screen-sized dimensions and sets an explicit bar-sized exclusive zone
(or zero/another reservation according to settings and plugin state).
The visual island is an Item inside that large surface, not a PopupWindow
anchored to a compact widget. Its child Loader changes between compact and
expanded plugin views.

The host clamps target width/height to its available size and clamps the
along-edge position (`anchoObjetivo`, `altoObjetivo`, `aLoLargo`, lines
879–906). It aligns expansion around a compact-pill reference centre and
supports different edges for different views. Changing edges deliberately
disables size interpolation briefly (`cortando`, 32ms timer).

**Intent:** comments at host lines 326–343 describe unwanted visual motion
when changing edges and explain the deliberate cut. Those historical
upstream observations were not reproduced here.

**MAGI relevance/proposal:** this demonstrates a combined bar/menu canvas,
distinct from placing a new shared overlay above MAGI's existing bar. It
can avoid inter-window seams, but adopting it would change bar hosting,
reservation, masks and positioning together. It is not a drop-in
ExpandablePlugin content implementation. Test P1/P4/P5 below before drawing
any conclusion about visual quality or compatibility.

## K02 — Plugin state survives view replacement

**Verified source:** [Plugin.qml:43–97][contract] separates plugin state from
the Component view. [shell.qml:1318–1338][host] creates Loader delegates for
the published instances, but activates a Loader only when its plugin is
the visible selection and `viewLoaded` is true. Losing selection therefore
deactivates the Loader; it does not merely set opacity to zero. Plugin
objects remain in PluginManager until explicitly removed/reloaded/disabled
through its lifecycle. `_crear()` creates them dynamically; `_destruir()`
removes references and calls `destroy()` ([manager][manager]).

The idle plugin can have views on multiple outputs while sharing one plugin
state object. Only the selected output displays the expanded global winner.
Arbitration does not generally close every losing plugin: enabled active
losers can become visible again when a higher-priority winner closes.
`apartarTransitorios()` explicitly closes active transient losers when a
non-transient winner appears. This is a priority system, not MAGI's single
requested-ID policy.

**MAGI relevance/proposal:** a nonvisual plugin/session object plus a
replaceable Component is adaptable without changing MAGI's popup host.
However, MAGI currently retains Loader content through closure. Importing
K4's unload-on-deselection rule would reset view-local drafts/scroll/focus
and remove view-owned observers before MAGI's outgoing fade completes.
Keep outgoing content until its own close completes; decide persistence
explicitly. P2/P3 must check rapid reselection and object lifetimes.

## K03 — Geometry morph and content entry are independent

**Verified source:** [shell.qml:937–1025][host] uses Behaviors: width 440ms
OutBack with overshoot 0.42; height 400ms OutBack with overshoot 0.32.
Position/fraction have additional 440ms behaviors. Width and height change
together; there is no equivalent of MAGI's widen-then-reveal phases.
The inner content stage uses requested target dimensions while its parent
clips the animated island (`shell.qml:1262–1338`).

[Aparicion.qml][appearance] starts at opacity zero and changes to one on
Component completion, with a 220ms OutCubic Behavior. [PanelView.qml:9][panelview]
uses its core FadeIn alias. This is an entry effect when the view is created,
not a host-level outgoing/incoming crossfade. Deselected views are unloaded
immediately by K02; the host's size animation can continue independently.
Panel navigation changes `tab` and requested height (280 for controls,
404 otherwise), rather than pushing a general host navigation stack.

**Interruption:** geometry is binding/Behavior driven; new targets can
retarget during a morph. No explicit seven-phase/generation protocol governs
these particular host size Behaviors. Cross-edge cuts disable them.
Separate gesture animations explicitly stop/reset one another, but that
does not establish interruption semantics for all plugin content.

**MAGI relevance/test:** retain MAGI's current sequence as the baseline.
Compare concurrent morphing and target-sized clipped content in P1/P2;
measure first-frame construction and reversal, rather than judging duration
or easing names as evidence of smoothness. Velocity continuity and clipping
at OutBack overshoot remain unmeasured.

## K04 — Input policy is centralized but configurable

**Verified source:** [shell.qml:399–405, 699–747][host] conditionally combines
the island input region with a full-surface click catcher. Outside dismissal
applies only on the active output, to expanded non-transient views that
allow it, and is disabled while the island is displaced/absent. The catcher
calls the visible plugin's `close()` for left/right/middle taps. Comments
explicitly intend the closing click to be consumed, not forwarded.

At lines 585–607 the host chooses None, Exclusive for `grabKeyboard` (or
hover keyboard policy), or OnDemand for optional keyboard use. Its Item
handles Escape by calling `close()` and reclaims item focus when no active
focus item remains (lines 991–1007). Content can consume keys before they
reach this ancestor. [PanelPlugin.qml:46][panel] requests keyboard grabbing
while open. It also opts into hover-exit closure; the host's timer consults
the current active plugin, whose handler may suppress closure.

[FocoInicial.qml][focushelper] requests focus immediately and retries at
140ms intervals with a six-retry cap. This is an upstream workaround,
not a Quickshell readiness guarantee.

**MAGI relevance/test:** declarative focus/dismissal preferences and one
close-request interface are useful contract ideas. Exclusive keyboard
policy and a screen-sized click catcher are significant behavior changes.
P4 must establish actual focus restoration, click consumption, hover-exit
behavior during typing and overlapping surfaces; do not copy the retry
timer as a substitute for a lifecycle design.

## K05 — Navigation and system work are partly outside views

**Verified source:** [PanelPlugin.qml:51–89][panel] owns tab changes and binds
Wi-Fi scanning to open-plus-Wi-Fi-tab and Bluetooth discovery similarly.
`openTab()` clears/cancels specified Wi-Fi UI state. PanelView's application
action closes the panel then calls `PluginManager.abrirAplicacion()`
([PanelView.qml:500][panelview]). Registry-driven creation and injected
references provide extension points, but plugins share a process and can
refer to each other; this is not a security sandbox or proof of independent
modules.

**MAGI relevance/proposal:** retain durable operations outside transient
views and make navigation/session activation explicit. Do not transplant
K4's Wi-Fi service: MAGI's own known/open/PSK paths, scan handoff, pending
feedback and password entry remain the preservation boundary documented in
`docs/architecture.md`. Source separation alone does not prove safe cleanup
of every operation when a plugin is disabled. P3 should use a fake async
service first.

## Compatibility with MAGI's installed environment

Target: **Quickshell 0.3.1, Qt 6.11.2, Hyprland 0.56.2**, as locally verified
in [the reference](../quickshell-reference.md). [dependencias.tsv][deps]
names Arch Quickshell/Hyprland dependencies but does not pin these versions.
This investigation does not certify that all of K4 runs on this stack.

- PanelWindow, Variants, Region, WlrLayershell and keyboard modes exist in
  [v0.3.1](https://quickshell.org/docs/v0.3.1/types/Quickshell/PanelWindow/).
  Explicit exclusiveZone separates reservation from visual menu height.
  A source declaration is not proof of compositor reservation behavior.
- Logical screen geometry is compatible in principle; K4's output-name
  routing is useful evidence for a future multi-monitor host. Test a removed
  active output and mixed scaling: the inspected routing functions do not
  establish a complete hotplug recovery policy.
- K4 sets both `focusable: true` and a more specific keyboardFocus binding
  on its host. In [Quickshell 0.3.1 source][qsfocus], `setFocusable(true)`
  sets OnDemand, not Exclusive. A MAGI experiment should have one explicit
  keyboard-mode owner and test initialization/changes rather than copy both.
- Auxiliary [K4.Ventana][window] is itself a PanelWindow wrapper, used by
  Settings and Dual. Thus “one shared surface” describes the island route,
  not every K4 feature. Fullscreen mask and auxiliary-window interactions
  need separate evaluation; Dual's complete motion system was not audited.

## Proposed local experiments — not executed

Only after approval, in an isolated fixture with fake content/services:

| ID | Experiment | Evidence required |
| --- | --- | --- |
| P1 | Compare MAGI's exact staged popup baseline with same-surface concurrent width/height morph | Frame timing, visible seam, actual geometry, clipping and unchanged desktop reservation; use identical content and hardware. |
| P2 | A→B→A and close/reopen during every stage; change dimensions/edge mid-motion | Final request wins; no blank frame, stale completion, unwanted cross-edge travel or orphan input owner. |
| P3 | Retained view versus unload-on-selection-change; fake delayed service result | Creation/destruction counts, preserved session state, no callback into destroyed content, no loss of pending feedback. |
| P4 | None/OnDemand/Exclusive, Escape, click outside, bar click, hover leave, text input | Actual keyboard recipient and restoration; exact consumed/forwarded click policy; no invisible controls or hover timeout while editing. |
| P5 | Two outputs, fractional scales, near-edge oversized content, simulated output loss | Logical geometry, target-output selection, bounded content, valid screen references, unchanged bar reservation. |

Unresolved: whether priority resurfacing suits MAGI, whether view recreation
causes measurable first-frame cost, how focus retries interact with rapid
replacement, and which sessions should persist. The source supports testing
these patterns, not replacing MAGI on aesthetic grounds. See the
[neutral cross-project comparison](serpantinum.md#technical-comparison-for-magi).
